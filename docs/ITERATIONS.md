## 2. 已完成的代码改造（三条，全部跑通）

### 2.1 支持「一节拆成多段」——学长说的拐弯

旧 build_mjcf.py 是"LINKS 一行 = 一个 body"，没法表达拐弯。改法：

```
LINKS = [
    ("L2_upper_a", (0.090, 0.000, 0.000), 0.030, 0.080, "估计"),  # M2 -> 拐点
    None,                                                          # <- 折点占位，不建关节
    ("L2_upper_b", (0.090, 0.022, 0.000), 0.030, 0.080, "估计"),  # 拐点 -> M3
]
```

解析规则：None 之后的那一段不新开关节，而是变成上一段的**子体**，位置 = 上一段末端。几何上连成折线，动力学上仍是一节。

**验证结果**（把 L2 拆成两段跑）：

| 指标 | 拆段前 | 拆段后 |
|---|---|---|
| nq（关节自由度） | 7 | **7**（没多出来） |
| nbody | 9 | 10（多一个折点 body） |
| njnt | 7 | 7，关节名完全一致 |
| 末端 x | 0.445 | 0.535（按新长度算的，符合预期） |
| 关节数校验 | — | 节数≠关节数时直接抛异常，防止 None 插错 |

老格式（7 行、无 None）跑出来**和改造前逐位一致**，向后兼容。

### 2.2 半径不再被静默夹取

旧代码 r = min(radius, 0.45*L)，超了不吭声。实测旧模型三段被砍：

| 段 | 填的 r | 实际生效 | 被砍 |
|---|---|---|---|
| L4_wr1 | 26 mm | 19.74 mm | **-24%** |
| L5_wr2 | 26 mm | 19.74 mm | **-24%** |
| L6_wr3 | 24 mm | 17.32 mm | **-28%** |

**所有基于旧模型的自碰撞结论都偏乐观**——仿真里的腕部比真机细 1/4，真机更容易撞。

新脚本每次都打印：

```
段名                   填r      生效r       长度   备注
  L4_wr1             26mm     20mm     44mm   << L 太短(r 被夹到 0.45L)
```

**上面这个块是旧版的原始输出，别拿里面的 `44mm` 去对账。** 三个坑：

1. 旧版打印是整毫米；现在的格式是 `%6.1f`，一位小数（当前跑出来 `L5_wr2 43.9mm`、`L6_wr3 38.5mm`）。
2. 即便一位小数也不够：真实轴心距是 **43.8634 mm**（向量 `(0.040, 0.018)` 的模长），
   `0.45 × 43.8634 = 19.74`；拿 `44` 去乘会得 `19.8`。**44 从来不是输入值**，
   它是"两个分量都是整数毫米、合成后不是整数毫米"再取整的结果。
3. 所以对账要用**未取整**的轴心距，见 `docs/BASELINE.md` §4 表下的算式。

本页 §2.2 的 `43.86 / 38.48` 就是未取整值，和这张旧表里的 `44 / 38` 说的是同两段。

## 7. 测量方法说明（为什么这样量、这样建）

### 7.1 为什么量「关节中心 → 关节中心」，而不是量连杆边长

学长第一反应可能会想量"这块铝板多长"。**不量这个，量关节中心到关节中心的距离。**

理由：
- MuJoCo 里每个 body 的 pos 就是**下一个关节相对于上一个关节**的位置。整个运动学只认这一个量，量错了整条链就错，量对了链就一点不差。
- 连杆的**实际外形边界**（板有多长、有没有伸出轴心之外）对碰撞只需用一个数近似——胶囊半径。这个数用"截面多宽"就能定，误差 5mm 无所谓。
- 反过来，"板长 180mm"这种量**没法直接用**：板的两端不一定都在关节中心上，还得再减掉铆接余量、轴承座厚度……每多一次加法就多一次错。
- 一句话：**长度误差直接进模型，外形误差只进半径。**

### 7.2 拐弯怎么写

LINKS 是一串 (名字, 到下一个关节的向量, 半径, 质量, 来源)。要拐弯就在中间插一个 None：

```
LINKS = [
    ("L2_upper_a", (0.090, 0.000, 0.000), 0.030, 0.080, "实测"),  # M2 -> 拐点
    None,                                                          # <- 折点，不建关节
    ("L2_upper_b", (0.090, 0.022, 0.000), 0.030, 0.080, "实测"),  # 拐点 -> M3
]
```

None 之后那一段不新开关节，变成上一段的**子体**，位置 = 上一段末端。所以：

- 段数可以从 2 段拆到 3 段、4 段，None 就是一个折点
- 关节数永远不变（build_mjcf.py 会校验：节数 ≠ 关节数直接抛异常）
- 向量全部写在**父连杆局部坐标系**里，拐弯的每个折点用自己的局部原点

学长描述拐弯的最省事办法：**"从 M2 往手臂方向走 90mm，然后往外拐 22mm，再走 90mm 到 M3"** —— 两句话，对应上面两行。

### 7.3 尺子不准的备选方案：A4 纸当标尺

如果尺子一直不准，**不用再量了，拍照片**：

1. 机械臂摆成**完全伸直**（M2/M3 都到 0°，能摆直就摆直）
2. 桌上紧贴机械臂立一张 **A4 纸**（210 × 297 mm，纸的尺寸有国标，比任何尺子都准）
3. **手机正对着拍**，镜头垂直于手臂所在的平面，别斜着拍
4. 照片丢给我

我怎么算：A4 纸的长边 297mm 在图里占 N 个像素 → 得到像素/毫米比例 → 把每个关节中心在照片里的位置量出来 → **全部 7 段长度一次到位**，误差 2~3%（手机镜头的透视畸变是主要误差源，正对着拍可以压到 2% 以内）。

**这个方案的额外好处**：拐点位置、U 型支架的横向偏置、截面宽度，都能从同一张照片里读出来。一次拍摄解决全部 7 段，不用再问 4 轮。

**限制**：拍不出深度方向（垂直于画面的那 5mm 偏置），那几项还得量或估。但手腕的横向偏置通常在画面平面内，能拍到。

### 7.4 缺数据怎么办

arm_params.py 里每一段都带来源标记：

- [实测] = 学长量过 / 舵机回读
- [估计] = 照片反推或常识占位
- [待测] = 明确知道要量，还没量

**不编数**。缺的地方宁可留着旧估计值并标 [估计]，也不填一个看起来合理的假数字——假数字会让碰撞结论看起来"很像那么回事"，比缺数据危险得多。
